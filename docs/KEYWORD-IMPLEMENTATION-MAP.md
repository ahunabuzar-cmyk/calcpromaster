## How to read the decision rules

A decision is produced by the first rule that matches, and the rule is printed with the row:

1. **E** — the answer needs a live external feed (weather, a brand menu, a league scoring table) or official
   jurisdiction rules we cannot verify from the repo. No fabricated data, so no page.
2. **D** — a second keyword in this audit normalises to the same intent (generic tail words dropped,
   plurals folded). One page must own the cluster.
3. **B** — every concept token already matches an existing registry tool, or the audit maps the keyword to a
   live sitemap URL. Improve that page; never create a duplicate calculator.
4. **C** — only a partial tool match. Resolve with internal links / metadata before any new page.
5. **A** — nothing matches: a genuine candidate for a standalone calculator.

Priority: **P1** = code A with volume ≥ 100k, or code B with volume ≥ 50k · **P2** = remaining A/B/C/D ·
**P3** = E (no implementation). Volume/difficulty/CPC come from the audit row and are never estimated here.
