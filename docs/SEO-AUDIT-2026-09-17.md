## 3. Technical SEO — Detail

### Jo sahi hai (verified)
1. **Serving contract ab clean hai:** extensionless garbage URLs true-404 dete hain (custom 404 page + status 404), real files hamesha jeet-te hain, SPA fallback sirf whitelist par. Ye bug kal tak tha (soft-404 = 200 on garbage) — fix ho chuka, live verify + playwright tests pin kar diye + CI gate laga diya.
2. **Canonicals:** 1,247 self-canonical; 183 variant pages (e.g. `/finance/loan-emi/9-years-777`) parent par canonical + noindex — duplicate-content risk zero. (Ek minor polish neeche note #1.)
3. **Schema markup:** tool pages par FAQPage + HowTo + WebApplication + BreadcrumbList — rich-result eligible. Home par Sitelinks SearchBox schema.
4. **robots.txt:** sab major + AI crawlers (GPTBot, ClaudeBot, PerplexityBot...) allowed, Sitemap ref sahi domain par.
5. **IndexNow** (Bing) wired hai, GA4 wired hai.
6. **Redirect hygiene:** live par sirf trailing-slash 301s hain (Netlify pretty URLs) — sitemap URLs final 200 par khatam hote hain. Koi redirect chain issue nahi mila.
7. **Performance posture:** 0 blocking scripts in head, home HTML 66KB, calculator data category-wise lazy. (Field CWV data available nahi — note #4.)

### Technical issues (chhote, priority-order mein)
1. **Canonical slash-mismatch (minor):** prerendered canonical `/finance/loan-emi` (no slash) par hai, par live serving `/finance/loan-emi/` ko 200 deti hai aur no-slash ko 301 karti hai. Google isse handle kar leta hai, par cleaner hoga ke canonical served URL se match kare. **Fix:** prerenderer mein canonical ko trailing-slash form mein emit karwana (1-line change in build) — ya Netlify par slash-less serving.
2. **`/guides` aur `/blog` par og:image missing** — sirf 2 pages, fix trivial.
3. **`tool-intros.js` = 668KB** (per-tool unique intros ka shared file). Har tool page par async load hota hai (render block nahi karta, theek), par gzip ke baad bhi heavy hai. Long-term: category-wise split.
4. **CWV field data:** CrUX report is domain ke liye available nahi hui abhi (traffic kam hai) — lab numbers acche hain, par Lighthouse CI / PageSpeed se monthly track karo.

## 5. Content Quality + Semantic / Topical Mapping

### Topical map (jo deploy structure se verify hua)
```
Home (1,320-word deep content + 20 category cards)
├── 20 category pages (/finance, /health, ...)
│   └── 1,201 tool pages (har page: calculator UI + ~100-word unique intro
│       + flagship tools par 30-section deep-dive + FAQ schema + formula transparency)
│       └── /hub/<category> comparison pages (20) — side-by-side tables
├── 63 guides (informational intent: "How to Calculate Percentage...")
├── Glossary
├── 6 blog posts (opinion/explainer)
└── Trust layer: About, 3 Disclaimers, Formula QA Dashboard (public verification)
```

**Ye textbook topic-cluster architecture hai:** tool pages = transactional intent ("loan emi calculator"), guides = informational intent ("how to calculate emi"), hub = comparison intent. Internal links dono ko jodte hain. Search intent mapping sahi hai.

### Content strengths (verified)
- **Formula transparency:** har calculator apna formula + step-by-step dikhata hai — "verify the math instead of trusting a black box" — Ye E-E-A-T ke liye genuinely achha signal hai.
- **QA dashboard:** public formula-verification dashboard rare hai — trust differentiator.
- **Unique intros:** har tool par ~100-word unique intro (generated, per-tool data file se) — template-duplicate nahi.

### Content weaknesses (sach)
1. **Blog 6 posts hain** — content velocity ke liye bahut kam. Guides (63) behtar hain, par bade competitors ke 500+ article clusters ke saamne thin.
2. **Guides mein visual content nahi hai** (0 images/tables in sample) — dwell time / engagement signals ke liye worked-example screenshots, comparison tables add karo.
3. **Author/E-E-A-T page nahi:** finance/health = YMYL. "Who reviewed this?" ka jawab site par nahi hai. Author bio + credentials + "last reviewed" dates add karo — YMYL rankings ke liye ye ab ranking factor hai.
4. **Locale URLs (`/es/...`) translated content nahi serve karte** prerendered form mein (SPA shell English) — par ye pages sitemap mein nahi hain aur canonical home par hai, to duplicate risk nahi. Jab tak translated prerendering + hreflang nahi banate, switcher ki locale URLs Google ke liye invisible hain — theek hai, koi nuksan nahi.
